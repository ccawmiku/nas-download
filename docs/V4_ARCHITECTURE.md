# v4 重建

v4 重写了控制台、任务调度、持久记录与媒体处理。X/Pixiv 的下载代码、已固定版本的 F2 和小红书实现继续作为平台适配依赖。旧平台 HTML 与内置调度不再作为用户入口。

## 服务职责

| 服务 | 职责 |
|---|---|
| console | 唯一网页/API、可选密码登录、SQLite 任务/媒体记录、增量检查点、日志、上游版本检查 |
| engines | X/Pixiv/抖音任务；每个平台最多一个执行任务；独立子进程执行和分钟时限 |
| xhs | 固定版本 XHS-Downloader 的适配执行，继续保留上游 ID 数据库 |
| telegram-worker | 复用既有 Telethon 功能，SQLite 历史、下载控制、交付恢复；仅内部 API |
| media | 单任务转换/校验/入库，N95 核显 HEVC、PNG/JPEG、防膨胀 |

网页分为总览、下载、工作区、媒体记录、平台与设置、日志。平台配置和系统配置均在设置页；Telegram 的下载控制位于下载页。默认日志显示 30 行，完整日志分页/导出。平台失败和达到时间上限分别显示，不归为完成。

## 停止与记录

- X 点赞：保存来源首条 ID，下一轮遇到该边界或 GraphQL 的底部终止信号结束。页面停止推进只表示未完成。
- Pixiv 收藏：公开/私密分别保存边界，按 API 的 next_url 分页，遇到边界或真实末页结束。
- 抖音点赞/收藏/作品：每个来源独立保存边界，按 F2 返回的 has_more 和作品 ID 判断结束。
- 首次同步正常处理新内容；连续已下载默认 X 10、Pixiv 20、抖音 50，沿用原配置字段并可在网页修改（1–1000）。重复曝光只计一个作品，失败/处理中/过滤不算已下载。X 按批采集与下载，Pixiv 每个收藏范围独立计数，抖音按真实文件结果计一个作品。边界/标记/明确末页仍可结束；异常或超时不推进当前来源边界。手动链接和失败重试不受连续阈值限制。
- 小红书文件队列首轮仅记住既有链接，后续只处理新链接；新失败内容按等待时间和次数上限自动重试，导入的历史失败不自动重试。
- X/Pixiv/抖音另外有 1–1440 分钟的运行上限，默认 15 分钟。时限结束是 limited，保留未完成状态。
- 采集边界和每项下载结果分开持久化。下载失败不会因下轮停止在旧边界而丢失重试入口。
- SQLite WAL 保存任务、资产、来源记录与日志。任务执行带 owner/attempt 和租约，重试后的旧进程不能写入新执行结果。

## 新媒体流程

下载完成 → 工作区交付 → 转换/验证 → 无覆盖入库 → 确认持久记录 → 删除工作区原件。

Telegram/小红书默认开启工作区，其他平台默认关闭，全部可切换。工作区没有暂停操作。处理服务不可用时，新文件绕过转换；已排队文件由执行服务校验后原件入库。正在处理的文件保留原件和恢复记录。

视频使用 hevc_qsv，quality=18、slow、async_depth=1，输入速度 0.5 倍，不改变分辨率和帧率，音轨复制。DSM 的内核不支持 Docker CPU CFS 配额，因此媒体进程绑定一个 CPU、nice=19、I/O idle；仅一个转换并行。没有 CPU 编码兜底。已有 HEVC 不重复编码。

验证封装、流信息、尺寸/帧率/时长/音轨，并读取首尾短片段；不做全长解码。无法证明原视频有效时保留工作区原件、标记失败。转换失败自动重试一次，再失败则归档有效原件。候选体积不小于原件时丢弃候选。

PNG 转 JPEG quality=95、subsampling=0，尺寸不变，保留 ICC/EXIF。实际透明或动画 PNG 原件入库；JPEG 不更小也保留 PNG。其他图片格式原样入库。

交付确认丢失时重放同一资产 ID；入库保存源、目标、SHA256、字节数与最终路径的收据，完整文件原子发布，不覆盖同名已有文件。记录确认前不删除原件。重启恢复只读取新工作区收据和下载历史，不扫旧媒体。

## 上游管理

F2 固定使用 ccawmiku/f2 的 5828ea7；XHS 固定使用 2.8-nas.2，继续隔离。核心通过适配器调用公开接口，并保留现有修复；不把上游源码变成核心的一部分。首页每 6 小时检查官方 release/分支以及修复分支 commit，展示候选，由人工评估和验证后升级。

五个 v4 镜像分别构建。平台基础依赖目前由 v3.0.3 已发布镜像固定提供，后续可以迁出独立依赖构建，当前不会同时重写平台协议与签名实现。

## Telegram 与累计空间

Bot 初始连接在后台执行，启动失败持续退避重试（3/6/12/24/30 秒），遵守 Telegram FloodWait；90 秒未完成的首次尝试清理后重试。凭证错误显示待修复，保存设置或手动重连后重新尝试。监督连接任务和下载处理任务，单独恢复退出的处理任务并保留队列。正常网页只有重新连接及下载暂停/恢复；v4 的停止 Bot API 返回 409，服务正常关闭仍可清理连接。预览禁用 Bot 连接。

`/api/controls/limit` 保留 `megabytes_per_second`（数字启用、null 关闭），新增 `limit_mb` 用于关闭时保存输入值。网页与 `/limit` 命令共同写入 `limit_enabled` / `limit_mb`，默认 false / 2 MB/s。Bot 状态补充 `connection_status` 和 `retry_at`。

`/api/workspace` 增加 `saved_bytes_total`，按已确认 complete 的资产正向原大小减入库大小汇总；同一资产重试/重复确认只贡献一次。界面以十进制 GB 显示，从新版开始累计，旁路及保留原件贡献为零。内部新增最多 100 个来源 ID 的批量记录查询，避免采集时逐条发 HTTP。任务结果/progress 增加 `known_consecutive` / `known_threshold` / `stop_reason`，多来源保留 `sources` 明细。
