# Instagram 收藏下载

仅同步当前登录账号的全部收藏（包括收藏夹中的作品），不下载点赞、关注列表或任意输入链接。适配器复用固定版本 **gallery-dl 1.32.16** 的 Cookies、请求头和媒体解析；严格分页、去重、恢复和停止由本项目管理。

## 设置

在“平台与设置 → Instagram”粘贴浏览器导出的 **Netscape Cookies 文件内容**，包含 `sessionid` 和 `ds_user_id`，选择对应浏览器类型。凭证保存在私有配置目录，不返回网页明文。先点击测试连接，再启用定时同步。

周期字段默认 **72 小时**，和其他平台一样需要打开定时开关；已有平台的周期不变。单次运行上限默认 15 分钟，超时或取消会显示未完成，不更新收藏边界。首次收藏很多时可调大上限，或分多次运行；已完成的文件会去重跳过。

Compose 默认目录与其他平台同层级：

| 用途 | NAS 路径 | 容器路径 |
| --- | --- | --- |
| 图片 | `/volume1/se-p/ins-p` | `/downloads/instagram/images` |
| 视频 | `/volume1/se-v/ins-v` | `/downloads/instagram/videos` |
| 配置 / Cookies | `${NAS_DOWNLOAD_ROOT}/platforms/instagram/config` | `/config/instagram` |
| 下载恢复状态 | `${NAS_DOWNLOAD_ROOT}/platforms/instagram/state` | `/state/instagram` |

Docker Compose 会创建缺少的绑定目录。确认运行账户有读写权限。工作区默认关闭，可按其他平台的方式开启。

## 获取与去重

收藏通过登录态 `/api/v1/feed/saved/posts/` 分页获取，每页最多 50 条。正常同步直接使用收藏响应中的图片、视频 CDN 地址；只有重试未完成下载时才请求作品详情刷新地址。CDN 下载使用单独会话，不携带 Instagram 登录 Cookies。

文件按 `帖子ID_媒体ID` 命名，轮播里的图片和视频分别归档。整条作品所有媒体都下载并校验后才算完成；转换中的作品不算已完成。下载核对响应类型、长度、图片结构，视频检查封装和首尾少量片段。使用临时文件及无覆盖发布；已有未知或被改动文件不会被覆盖。直接归档文件记录大小和 SHA-256，工作区成品沿用媒体服务的校验与持久记录。

下载恢复清单在发布文件前持久化。重启或中断后复用已经校验的文件，只补缺少部分。失败作品保留已有文件，自动尝试上限默认 3 次；同步前先重试失败下载，以免其位于停止边界之后而被遗漏。手动“重试失败”可再次尝试。媒体转换失败请使用工作区重试，避免无意义地向 Instagram 重取详情。

收藏边界按登录账号分别保存；媒体记录按作品共享，不重复下载同一作品。取消收藏不会自动删除已归档文件。

## 自动停止

满足任一条件结束本次采集：

- 到达上次成功同步的作品，且该作品文件仍完整。
- 连续 **20 条不同作品**已有完整成功记录（可调整）。重复返回的作品不重复计数；遇到新作品、下载失败或处理中会重置连续数。
- 接口明确返回 `more_available=false` 的末页。

缺少分页字段、空页却声称有下一页、重复游标或无新作品的循环页均视为异常。未完成下载、等待转换、异常或超时不推进边界；已下载文件和失败记录保留，下次继续。新下载完成的作品不会在同一轮被当作“历史已完成”计数。

API 请求默认间隔 30–60 秒，媒体下载 5–10 秒。遇到登录检查、challenge、403、429 或其他接口失败立即停止，不自动重登、不处理验证挑战、不循环重试。下一次定时任务仍按正常周期触发，账号提示异常时应关闭定时、先在浏览器检查账号。以上控制减少重复请求，不能保证账号不会受限制。

## 版本与验证

本功能从 `v4.0.4` 开始提供，五个服务应使用同一发布版本。升级时先使用独立配置、状态、媒体目录和端口进行验证，符合 [重建约定](REBUILD_CONTRACT.md)。正式切换前停止并删除旧容器，清理旧版本服务镜像，再创建新容器；保留原配置、状态、session 和媒体文件，避免群晖同名容器残留冲突。

自动测试使用固定版本的真实 gallery-dl 解析器和模拟接口，覆盖分页、混合轮播、部分失败恢复、SHA-256 去重、停止边界及账号隔离。真实收藏列表、Cookies 有效性和账号风控需要配置账号后做小批量验证。
