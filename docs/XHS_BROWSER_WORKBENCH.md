# 小红书 NAS 下载工作台

安装或替换 `tools/userscripts/xhs-docker-queue.user.js`（3.1.0），脚本菜单名称改为「小红书 · NAS 下载工作台」。沿用原 namespace、Docker 地址、端口、接收路径和推送授权存储键；启动时不再弹出说明或警告。升级时推荐在油猴编辑器中替换旧脚本全文，以保留存储；若作为新脚本安装，请停用旧脚本并重新填写连接配置。新面板专注 Docker 队列，不再依赖 JSZip 或 WebSocket，也不执行浏览器本地下载。

## 点赞、收藏批量发送

1. 登录小红书，打开目标账号主页，点击左下角「NAS 工作台」。
2. 选择点赞或收藏。「读取已加载」切换到相应标签并读取列表；「自动加载」逐步滚动，直到遇到截止作品、连续五次没有新增、达到设置次数或手动停止。
3. 点击某张作品卡片的「设为截止」，也可粘贴完整作品链接或作品 ID。截止条件使用作品 ID，而不是标题。
4. 点击「发送范围内作品」。按网页列表顺序发送截止作品之前的作品，**不含截止作品**。若设置了截止作品但加载列表里找不到它，则阻止发送；可继续自动加载、修改或清除截止点。

手动截止点使用油猴持久存储，按账号主页 ID 和点赞/收藏分类分别保存，刷新和重启浏览器后仍保留。发送不会自动移动手动截止点。没有手动截止或自动记录时，发送当前已加载列表；脚本不会按发布日期重新排序。平台页面须按期望顺序显示。

### 自动保存最近 5 个作品（3.1.0）

点赞或收藏的批量链接全部得到 Docker 接收确认后，自动保存本次发送的最新 5 个作品 ID、标题及顺序，按账号和分类隔离。下次自动加载和发送都会使用这组记录，无需重新手选截止作品。

例如上次记录为 `A → B → C → D → E`，下次列表为 `新1 → 新2 → B → E → 更早作品`：虽然 A、C、D 被删除，只要剩余的 B、E 顺序一致，就只发送新1、新2，B 及后面的内容不发送。匹配不要求连续，允许其他作品穿插。

- 至少匹配两个保存过的作品，且所有当前已出现的记录须保持原顺序。若只出现一个或顺序颠倒，不采用自动截止；可继续加载、设置手动截止或清除自动记录。
- 初次本来只发送了一个作品时，保存一个并按该作品截止。此后新增不足 5 个时，补入上次已确认的记录，尽量持续保留 5 个。
- 手动和自动截止同时存在时，在先遇到的位置停止，均不包含截止作品。任意一个有效截止都可使用。
- 未发送新作品、发送失败或停止后仍有未发送分组时，不更新自动记录。单独发送、发布和当前页面批量发送不会影响点赞/收藏自动记录。
- 面板显示最近记录及匹配数量，可点击「清除记录」仅重置当前账号当前分类的自动记录；原来的「清除」只清除手动截止。

这里的成功指 Docker 已确认持久入队，下载进度仍在 Docker 控制台查看。

批量请求每组最多 500 条，保留作品链接的 `xsec_token`。停止操作会停止后续加载或分组提交，已经送达 Docker 的任务继续执行。失败信息会显示已确认数量。作品链接和封面仅从当前登录用户可见的页面状态读取，不调用额外的私有签名接口。

发布、推荐、搜索和专辑页面可使用发布或当前页面分类。页面切换后需重新读取，避免发送上一账号的列表。

## 单个作品与 Docker 目录

- 打开作品后点击「使用当前作品」再发送，或粘贴带签名参数的完整作品链接。
- 列表中每张卡片也可「单独发送」，不受批量截止点限制。
- Docker 控制台 → 小红书 → 归档与命名 → 单个作品保存目录，对应配置键 `single_work_path`。
- 留空默认使用上游 `work_path` 下的 `single`（例如 `/xhs/single`）；上游的作品子目录和文件命名规则继续生效。
- 自定义值必须是容器内绝对路径。使用现有 `/xhs` 挂载内的路径无需修改 Compose；如选择挂载外的新路径，必须将其同样挂载到 xhs 和 media 服务，且加入控制台可浏览的媒体根目录。
- 单个任务独立于批量任务入队；同一作品已批量下载后仍能单独下载到 single。单个发送会跳过上游全局已下载 ID 检查，因此完成后再次单独发送会再次下载。
- 下载、工作区处理及失败重试都保留 single 保存类型。旧脚本不传保存类型时维持批量目录。

接口保持 `POST /api/xhs/links`，请求示例：

```json
{"urls":["https://www.xiaohongshu.com/explore/作品ID?xsec_token=签名"],"destination":"single"}
```

`destination` 可为 `batch`（默认）或 `single`；single 请求只能包含一条链接。浏览器授权仍使用 `X-NAS-Submit-Token`。目录由 Docker 设置决定，浏览器不能提交任意保存路径。

## 验证

```sh
node --test tests/test_xhs_userscript.cjs
python -m pytest tests/test_v4.py -q
cd frontend && npm ci && npm run build
```

可选浏览器回归：安装 Node 的 `playwright` 包并执行 `npx playwright install chromium` 后运行 `node tests/xhs_browser_smoke.cjs`；非默认浏览器路径可用 `PLAYWRIGHT_EXECUTABLE_PATH` 指定。

浏览器验证使用模拟页面状态和 Docker 接收响应，覆盖截止排除、五作品持久化、仅剩两个作品的有序匹配、自动停止加载、逆序拒绝、发送失败和分组停止保留记录、发送中切换账号隔离、左侧定位，以及签名保留和单个作品类型。真实小红书页面依赖其 DOM 标签和 `__INITIAL_STATE__` 结构；平台改版或不可见的点赞/收藏列表会显示读取错误，需在登录页面实测。
